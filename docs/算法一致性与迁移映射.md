## 对齐结论

纯 C++ 版已按 Python 版的配置、生成清单和控制规则逐项对齐。这里的“对齐”指同一输入、同一随机种子、同一 OD 规则、同一压力公式、同一安全状态机和同一 KPI 口径；由于 TESSNG 内部跟驰和并行调度存在随机性，不要求两次运行的每辆车坐标逐帧完全相同。

2026-09-07 的自动验收结果：源清单中的 J253/J254 已按一个合并交叉口处理，最终 254 个控制器、1036 个相位、1593 个外边界灯头全部创建；8 秒运行态检查中 2000/2000 辆预载成功、2000 辆绑定固定 OD、执行 1546 次动态路由决策、91 条展宽走廊的未连通数为 0、灯色回读异常交叉口数为 0。验收原始结果见 `generated/native_signal_build_report.json` 和 `generated/native_runtime_smoke_report.json`。

2026-09-08 路网人工修订后：J251 已删除西向东左转，J253-J254 已在 TESS 中物理合并且删除左转。两处仍保留控制器、相位、灯头和灯色回读，但所有现存直行/右转灯头永久为绿，不再参与固定配时或最大压力切换；当前构建为 254 个控制器、733 个相位、1592 个灯头。同步删除路由图中的 4430/4431/5672/5673 旧短 Link，并用实际直连关系替换，防止车辆继续按旧路由驶向不存在的连接。

## 输入文件一致性

下列 C++ 副本已与 Python 工程通过 SHA-256 核验，内容完全相同：`scenario.json`、`intersection_manifest.json`、`local_routing_manifest.json`、`dynamic_routing_graph.json`、`initial_traffic_plan.json`、`route_candidates.json`、`grade_separation_manifest.json`、`intersection_catalog.json`、`research_method_manifest.json`。

## 不变的大方向

- 对照分支仍为固定配时；默认分支仍为“云边端动态主从＋改进最大压力”。
- 每车从 22 对端点中确定一个固定终点，终点不变，途中只在 929 个合法决策点重新选择下一段。
- 车道展宽前完成决策，冻结区和 Connector 内不进行宏观换路。
- 信号相位仍使用冲突图生成的安全组合相位，优先双向兼容放行。
- 黄灯 3 s、全红 2 s、最小绿 12 s、最大绿 45 s；只有安全切换过程可以短时全红。
- 右转专用车道可常通；共享车道按物理车道整体放行，不拆分直行与左转灯色。

## 改进最大压力

原生 C++ 版的阶段评分仍包含：当前排队、15 s 预测到达、队列增长、下游排队、低速亏损、下游占有率回滞闸门、长期等待公平补偿、双向并行放行奖励和 RSU 可靠性。

`W = smooth[ Gdown · (Qin + Apred + 0.8ΔQ - 0.75Qdown) · Vdef · Ffair · Fparallel · Rrsu ]`

切换仍受最小/最大绿、压力比、最小收益、空相位 gap-out、服务饿饿和黄灯/全红损失约束。

## 效率设计

- 不加载 Python 3.6，不经过 Python/C++ 虚回调。
- 不使用逐批文件、HTTP 或网关传递控制帧。
- 每 100 ms 在 C++ 内存中执行灯色与安全车辆动作；每 1 s 聚合一次全网状态；每 5 s 重建 22 棵最短路径树。
- 信号灯始终只有一个 C++ 写入者，无影子模式。

## 刻意保留的实现差异

- 不嵌入 Python 3.6，不加载 PyTorch，不走逐批 HTTP/文件桥接；相同业务逻辑在一个 C++ 进程的内存中执行。
- Qt 面板在功能和数据口径上对齐，但不追求与 Python/PyQt 界面逐像素相同。
- 车型名称允许使用 TESSNG 内置本地化名称；车辆控制以稳定车型编码和 CAV 元数据为准。
