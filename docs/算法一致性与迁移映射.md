## 不变的大方向

- 对照分支仍为固定配时；默认分支仍为“云边端动态主从＋改进最大压力”。
- 每车从 22 对端点中确定一个固定终点，终点不变，途中只在 929 个合法决策点重新选择下一段。
- 车道展宽前完成决策，冻结区和 Connector 内不进行宏观换路。
- 信号相位仍使用冲突图生成的安全组合相位，优先双向兼容放行。
- 黄灯 3 s、全红 2 s、最小绿 12 s、最大绿 45 s；只有安全切换过程可以短时全红。
- 右转专用车道可常通；共享车道按物理车道整体放行，不拆分直行与左转灯色。

## 可逆改进最大压力

原生 C++ 版的阶段评分包含：当前排队、15 s 预测到达、队列增长、下游排队、下游预测占有率、占有率增长、低速亏损、下游占有率回滞闸门、长期等待公平补偿、双向并行放行奖励和 RSU 可靠性。

`P+ = Qin + wA·Apred + wG·max(ΔQ, 0)`

`P- = wD·Qdown + min(Bmax, wO·Opred^γ + wT·max(ΔO, 0))`

`Psigned = P+ - P-`，`Pusable = max(0, Psigned)`

`W = smooth[(Wmin + Pusable·Vdef·Gdown·Ffair·Fparallel·Rrsu)·Fwave]`

当 `Psigned < 0` 时，含义是下游拥堵形成的反压力强于上游服务需求，算法会降低该运动的相位竞争力。这里反转的是压力传播方向，不是车辆行驶方向：实现不会修改车辆方向、车道方向、Link 方向或路网拓扑。回溢硬门控继续优先于评分；切换仍受最小/最大绿、压力比、最小收益、空相位 gap-out、服务饥饿和黄灯/全红损失约束。

## 效率设计

- 算法、状态和诊断均在 C++ 进程内完成，不加载 Python 3.6，不经过 Python/C++ 虚回调。
- 不使用逐批文件、HTTP 或网关传递控制帧。
- 每 100 ms 在 C++ 内存中执行灯色与安全车辆动作；每 1 s 聚合一次全网状态；每 5 s 重建 22 棵最短路径树。
- 信号灯始终只有一个 C++ 写入者，无影子模式。

## 刻意保留的实现差异

- 不嵌入 Python 3.6，不加载 PyTorch，不走逐批 HTTP/文件桥接；业务逻辑在一个 C++ 进程的内存中执行。
- Qt 面板是 C++ 工程自身的诊断界面，不依赖 Python/PyQt 界面。
- 车型名称允许使用 TESSNG 内置本地化名称；车辆控制以稳定车型编码和 CAV 元数据为准。
